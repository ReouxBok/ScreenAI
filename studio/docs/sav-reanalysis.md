# Candidate-only reanalysis

This operator tool prepares a fixed cohort, generates separate encrypted candidates,
and exports a private comparison. It cannot adopt a candidate, change a decision,
open/unpause a dossier, enqueue an action, send mail, or write to CRM.
It has no HTTP route, cron or worker registration.

## Preparation

Run `node --conditions=react-server --import tsx scripts/sav-reanalysis.ts plan`
from `studio/`, with `--input`, `--target` and `--output` absolute private paths
outside the checkout. Input and target files must have permissions 0600.
The output is created exclusively with permissions 0600. Nothing loads `.env` files.

- Input: `{ since, until, pairs: [{ threadId, messageId }] }`, maximum 216 unique
  pairs. The operator supplies the frozen allowlist; the tool never expands it.
- Target: `{ projectId, teamId, databaseHash, codeRevision }`. Database hash is
  SHA256 of canonical JSON `{ database: url.pathname, host: url.hostname,
  port: url.port || "5432" }`. Credentials are not part of the hash or output.
- Trusted runtime: production Vercel project/team/code identity, production database
  with `sslmode=verify-full`, existing encryption/model access, explicit V0/nonpilot.
  The code identity must be independently verified against the deployed artifact.
  Environment strings alone are not a security boundary against a trusted operator.
- Plan queries are read-only. Cutover, exact dashboard views, latest inbound,
  technical/Other/external completion and unsettled actions are rechecked.
  Paused/human-requested dossiers may yield candidates; their flags stay unchanged.
- The generated manifest expires after one hour and freezes target, model, prompt,
  resources, exact messages and hashes of the existing operational state.
  Changed/excluded cases are listed; an old preparation manifest is not approval.

## Execution gate

Execution requires a **new explicit user authorization** on the deployed target,
manifest and selected tranche. No execution approval is generated by this tool.
The additional approval file is an operator receipt of that authorization, not
cryptographic proof of the user's identity. Never fabricate it from an old go.

`execute --input MANIFEST --target TARGET --approval APPROVAL --output RECEIPT`
also requires the process-local `SAV_REANALYSIS_EXECUTION_ENABLED=true` gate.
Approval schema: version 1, batchId, manifestHash (canonical SHA256), actor,
mode `candidate_only`, codeRevision, expiresAt, messageIds and stage `first`
(at most 5). `continuation` permits at most 20, names a separate
reviewedPreviousBatch and requires its claims to be ready at the same code.
The operator must inspect that previous comparison and obtain authorization;
the file and ready states cannot prove that human review occurred.

Concurrency is one. A durable claim is committed before model dispatch, under a
thread lock. The same message/snapshot/target cannot dispatch twice across
batches. A running claim after a crash is **uncertain**, never automatically
retried or stolen after a timeout. Reconcile it before any new authorization.
Normal AI budgets and validators apply unchanged; there is no executor retry.
Stop at the first stale, uncertain, failed or degraded result. Approval expiry is
checked between calls. A call already in flight can finish after cancellation
or expiry; it remains a separate candidate and never triggers an action.

Context collection reads CRM/history without persisting enrichment. Analysis
omits the ordinary persistence context. Only the audit claim and its encrypted
candidate envelope are written. `agent_runs` stays untouched so ordinary health,
conversation and learning readers cannot consume comparison records.
Freshness is checked before and after generation. No SQL lock is held during a
provider call. Changed source, human review/draft/action, pause or knowledge
quarantines the candidate. There is no automatic adoption, including for the
unprotected dossiers.

## Inspection and cancellation

`compare --input MANIFEST --target TARGET --output COMPARISON` reads the original
AI proposal, current human review/draft/verdict and encrypted candidate. The
private output contains customer content: retain it only in the private evidence
area. A current-state hash check marks stale comparisons. This export does not
change the dashboard. Provider usage traces are partial observations, not a full
billing total or a quality verdict.

`cancel --input MANIFEST --target TARGET --output RECEIPT` appends a cancellation
marker. It prevents the next dispatch and quarantines a call already in flight.
It does not revoke the provider's current HTTP request.

## Deployment prerequisite

This CLI needs a trusted process with existing production secrets. A developer
Mac without the decryption key cannot run a real plan or execution. Serverless
deployment does not automatically expose a CLI process. Before a real launch,
qualify that execution access (or separately review a server entry point), verify
the deployed code, generate a fresh plan and obtain the scoped authorization.
No production access, publication or real reanalysis is implied by local tests.
